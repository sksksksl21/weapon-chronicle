# Issue #3 — checkpoint recovery write failure

PR #2 was merged before branching from `74e4727`. The accepted change is limited to recovery I/O error handling and regression coverage. Gameplay/causality, narrative (five acts/40 chapters), UI/art, save keys/schema and module order remain unchanged. Runtime extraction and v5.5 development are out of scope.

`checkpoint_v483.js` now quarantines only parse/validation failures. A valid checkpoint remains byte-for-byte under its live key when recovery save/notice writes or checkpoint removal fail. All required writes precede cleanup. Notice removal remains independently retryable through the existing load wrapper. No migration is required.

The follow-up P1 fix distinguishes blocked recovery (`null`) from normal startup (`false`) and recovered startup (`true`). An unreadable checkpoint or SAVE_KEY blocks startup; SAVE_KEY read errors cannot prove whether a later-month save was already committed. A failed rollback write permits loading only if a readback proves the action-start snapshot or an already committed save is present. Otherwise neither the partial save nor a fresh month is loaded. The recovery dialog has no close button or backdrop dismissal, underlying controls are inert to pointer/keyboard input, and Retry reloads the app to attempt durable recovery again. Notice/cleanup failures remain non-blocking only when safe durable data can be verified. The normal game UI is unchanged.

The second review found that parseable JSON with a later date but no valid owner/weapon structure could incorrectly supersede the checkpoint. `v483IsDurablyCommitted` now requires `v48ValidateLoadedData(snapshot)` to pass, matching the normal loader. This shared check covers commit cleanup, startup recovery and post-error readback without changing keys, schemas or valid old-save migration. Two browser regressions expand the suite to 25 checks: a structurally invalid future-dated save must neither clear the checkpoint at commit nor lose the campaign at startup; with an additional rollback-write fault it must remain blocked until successful retry. A Node VM probe reproduced default GOLD 68/new-month fallback and checkpoint loss before this fix, and verified GOLD 345 recovery or blocked/preserved rollback afterward. See the PR for final results of the expanded suite and its exact remote HEAD.
