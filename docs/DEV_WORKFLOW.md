# GitHub dev 개발 흐름 안내

원하는 목표를 입력하면 다음 순서로 진행합니다. dev는 개발 결과를 모아 확인하는 브랜치(코드 작업 갈래)입니다.

1. **목표 입력**: 바꾸고 싶은 내용과 완료 기준을 쉬운 말로 적습니다.
2. **GitHub 최신 코드 동기화**: 원격 dev의 최신 코드를 가져옵니다. 원격 dev가 없으면 최신 원격 main을 기준으로 dev를 생성합니다.
3. **Codex 구현**: 격리된 작업 공간의 전용 브랜치에서 요청한 범위만 구현합니다. 이번 구현 작업은 `docs/DEV_WORKFLOW.md` 작성 1개입니다.
4. **Claude 독립 리뷰**: 자동 단계에서 Claude가 변경 내용과 누락·문제를 독립적으로 검토합니다.
5. **전체 기존 테스트와 필요 시 수정**: 자동 단계에서 전체 기존 테스트를 실행합니다. 리뷰나 테스트에서 문제가 발견되면 수정한 뒤 다시 리뷰·검사합니다.
6. **dev 병합·GitHub dev 반영**: 리뷰와 테스트를 통과하면 자동 단계에서 변경을 dev에 합치고 GitHub의 원격 dev에 반영합니다. 반영 직전에도 최신 원격 변경을 확인하고 보존합니다. 충돌은 해결하고 다시 검사하며, 강제 Push는 금지합니다.
7. **결과 확인**: 무엇이 바뀌었는지, 리뷰 결과, 테스트 결과, GitHub dev 반영 여부를 확인합니다. 실패하거나 보류된 단계가 있으면 함께 확인합니다.

리뷰·전체 기존 테스트·dev 반영은 이어지는 자동 단계이며 별도 구현 작업으로 만들지 않습니다. **main 병합과 배포는 사용자가 결정합니다.**

이번 변경은 이 안내 문서에만 한정합니다. 기존 주요 기획·저장 호환성·전투·설전·대화·아트 방향과 게임 소스·기존 테스트·설정 및 다른 파일은 변경하지 않습니다.
